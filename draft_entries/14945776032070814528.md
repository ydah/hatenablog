CLIツールのデモを簡単に作るため、`shellfie` というGemを作りました。

[https://github.com/ydah/shellfie:embed:cite]

<figure class="figure-image figure-image-fotolife" title="shellfieで作成したデモのGIF">[f:id:ydah:20260829220659g:plain]<figcaption>shellfieで作成したデモのGIF</figcaption></figure>

このGIF自体もshellfieで生成しています。元になっているYAMLはリポジトリの [examples/demo_animation.yml](https://github.com/ydah/shellfie/blob/main/examples/demo_animation.yml) に置いています。

このGemを作るきっかけになったのは、自分で作ったCLIツールのREADMEに、実際に動いている様子をGIFで載せようとしたことです。

CLIツールは、コマンドと出力をテキストで並べるだけでも使い方を説明できます。しかし、入力してから結果が表示されるまでをGIFで見せた方が、どのように操作するツールなのか伝わりやすいこともあります。

ターミナルを録画してみるというのがやることかなと思うのですが、これが思っていたよりも大変です。ウィンドウの大きさをいい感じにして、余計なプロンプトや履歴が映らないようにして、入力速度や待ち時間も調整する必要があります。途中で打ち間違えたり、出力のタイミングがずれたりすると、また最初から撮り直しです。

一度だけならそれでも良いのですが、更新するたびに同じことをするのは面倒です。そもそも、デモで入力するコマンドや表示したい出力は事前に決まっています。それなら、見せたい内容をYAMLに書いて、そこからGIFやターミナル上のデモの画像を作成できれば良いのではないかなと考えたのでした。

## shellfieとは

`shellfie` は、YAMLから端末の画像やアニメーションを生成するGemです。

大きく分けると、2つの使い方があります。

1. compose設定に表示内容を書き、静止画やアニメーションを生成する
2. session設定をPTY上で実行し、その結果を検証、記録、再生する

compose設定を扱う `generate` は、YAMLに書かれたコマンドを実行しません。コマンドと出力を描画するためのデータとして扱うので、実行環境に左右されず、毎回同じ画像やGIFを生成できます。

一方、session設定を扱う `run` と `record` は、YAMLに書かれたコマンドを実際に実行します。`replay` は記録済みのイベントから画面を再構成するため、元のコマンドは実行しません。

主な機能は次のとおりです。

- YAMLからPNG、WebP、SVG、HTMLなどの静的な表示を生成する
- GIF、アニメーションWebP、APNG、MP4、WebMなどを生成する
- macOS、Ubuntu、Windows風のウィンドウや、装飾のない表示を作る
- ANSIカラー、カーソル移動、画面消去、折り返しなどを描画へ反映する
- PTY上でコマンドやキー入力を実行する
- 画面、行、終了ステータスなどを待機、検証する
- 実行結果をカセットへ記録し、オフラインで再生する
- TXT、ANSI、JSON、asciinema v2のトランスクリプトを出力する
- JSON Schemaや、設定を検証、整形するためのコマンドを提供する
- GitHub Actionsや `generate --check` で生成物の更新漏れを検出する

静的な画像とアニメーションの生成はmacOS、Linux、Windowsで利用できます。PTYを使うsessionは、現在Windowsネイティブではサポートしていません。

## インストール

インストールは通常のGemと同じです。プロジェクトへ追加する場合は、`bundle add` を使います。

```console
bundle add shellfie
```

もちろん、グローバルにインストールして使うこともできます。

```console
gem install shellfie
```

画像の生成にはImageMagickを使います。また、MP4、WebM、APNGを出力する場合はffmpegも必要です。

## shellfieを使う

### まず静止画を作る

まずは、`echo hello` とその出力を表示する画像を作ってみます。

```yaml
version: 1
theme: macos
title: "Terminal"

lines:
  - prompt: "$ "
    command: "echo hello"
  - output: "hello"
```

このYAMLを `terminal.yml` として保存し、次のコマンドを実行します。

```console
shellfie generate terminal.yml -o terminal.png
```

これで、macOS風のウィンドウに `echo hello` とその出力を描画した `terminal.png` が生成されます。`shellfie` には、`shf` という短いエイリアスも用意しています（ちょっとコマンド名が長いですからね）

<figure class="figure-image figure-image-fotolife" title="出力される画像">[f:id:ydah:20260829222213p:plain]<figcaption>出力される画像</figcaption></figure>

設定には `command: "echo hello"` と書いていますが、`generate` は `echo hello` を実行していません。`command` と `output` は、どちらも描画するためのデータです。

README用の画像を作るために設定を読み込んだだけで、そこに書かれたコマンドが実行されるのは困ります。また、毎回コマンドを実行していると、時刻やネットワーク、外部サービスなどの影響で結果が変わってしまうこともあります。

そのため、compose設定には表示したい内容をそのまま書くようにしています。実行環境に存在しないコマンドや、説明のために簡略化した出力も表現できます。

もちろん、これだけではYAMLに書いた出力が実際のコマンドと一致していることまでは保証できません。見た目を毎回同じように生成したい場合はcompose設定を使い、実際に動くことまで確認したい場合は、後で紹介するsession設定を使います。

`theme` には `macos`、`ubuntu`、`windows` を指定できます。独自のウィンドウテーマやカラースキームを定義したり、装飾のないヘッドレスな表示を作ったりすることもできます。

### アニメーションを作る

続いて、`frames` を追加してアニメーションを作ってみます。

```yaml
version: 1
theme: macos
title: "Demo"

window:
  width: 600
  visible_lines: 8

animation:
  typing_speed: 50
  framerate: 30
  seed: 1
  loop: true

lines:
  - output: "Ready"

frames:
  - prompt: "$ "
    type: "echo hello"
    delay: 500
  - output: "hello"
    delay: 1000
```

次のように `--animate` を指定します。

```console
shellfie generate demo.yml -o demo.gif --animate
```

`type` は文字列が端末へ入力されていく過程を表し、`delay` はその後に表示を止める時間を表します。

冒頭に載せたGIFでは、コマンドを入力する様子と、続けて `validate` を実行するところまでを一つのデモにしています。手で録画しているわけではないので、YAMLを変更すれば同じ流れを何度でも作り直せます。

[https://github.com/ydah/shellfie/blob/main/examples/demo_animation.yml:embed:cite]

入力速度、フレームレート、再生速度、ループ、逆再生、ping-pong再生などを設定できます。GIF以外にも、アニメーションWebP、APNG、MP4、WebMへ出力できます。

また、各フレームのPNGと表示時間を記録した `timeline.json` をまとめたPNGシーケンスも生成できます。動画へ変換する前にフレームを確認したり、別のエンコーダーへ渡したりするための形式です。

表示できる行数を固定すると、出力が増えるにつれて画面がスクロールする様子も作れます。

### 実際のCLIを動かす

ここまでは表示する内容をYAMLへ直接書いていました。READMEに載せている手順が現在も動くことまで確認したい場合は、`version: 2` のsession設定を使います。

```yaml
version: 2
mode: run
title: "Recorded shell"
theme: macos

terminal:
  shell: /bin/sh
  columns: 80
  rows: 16
  timeout: 10s

steps:
  - type: echo hello from shellfie
    speed: 30cps
  - key: enter
  - expect:
      screen_contains: hello from shellfie
      exit_status: 0
  - capture: complete

outputs:
  - path: session.svg
    format: svg
    capture: complete
  - path: session.txt
    format: txt
```

次のコマンドを実行すると、指定したシェルをPTY上で起動し、`steps` を上から順番に処理します。

```console
shellfie run session.yml
```

<figure class="figure-image figure-image-fotolife" title="実際にPTY上でコマンドを実行したデモ">[f:id:ydah:20260829221723g:plain]<figcaption>実際にPTY上でコマンドを実行したデモ</figcaption></figure>

このsession設定も、実際に動かせる例としてリポジトリに置いています。

[https://github.com/ydah/shellfie/blob/main/examples/session.yml:embed:cite]

`type` は文字を実際に入力し、`key` はEnterや矢印キーなどを送ります。`expect` では、画面に指定した文字列が含まれていることや、終了ステータスが期待どおりであることを確認できます。`capture` で名前を付けた画面は、`outputs` から参照できます。

sessionでは、次の操作を組み合わせられます。

操作 | 役割
--- | ---
`run` | コマンドを直接実行する
`type` | 文字列を指定した速さで入力する
`key` | Enter、矢印キー、修飾キーなどを送る
`sleep` | 指定した時間だけ待つ
`wait` | 画面、行、プロンプト、プロセスの終了、画面の安定を待つ
`expect` | 画面、行、終了ステータス、カーソル位置、経過時間などを検証する
`hide` / `show` | 準備や後片付けを録画へ含めるか切り替える
`capture` | 途中の画面に名前を付ける

単純な `sleep` だけでタイミングを合わせようとすると、実行するマシンの速さによって録画が壊れることがあります。そのため、文字列が画面へ出るまで待つ、プロンプトへ戻るまで待つ、一定時間画面が変化しなくなるまで待つ、といった条件を記述できるようにしました。

長時間動くプロセスやTUIを操作する場合は、`async: true` で実行を継続し、`wait` で必要な状態まで同期します。ここでいうTUIは、端末上で画面を書き換えながら操作するインターフェースのことです。

### 実行と描画を分ける

実際のコマンドを毎回動かさず、録画した結果から画像を作り直したい場合は、`record` と `replay` を使います。

```console
shellfie record session.yml --cassette session.json
shellfie replay session.json -o session.gif --animate
```

`record` はsessionをPTY上で実行し、端末から受け取ったイベントとそのタイミングをカセットへ保存します。`replay` は、そのカセットから画面を再構成します。記録されたコマンドをもう一度実行することはありません。

編集しやすいYAMLとして録画することもできます。

```console
shellfie record session.yml --yaml editable-recording.yml
```

私が `record` と `replay` を分けた理由は、正しい手順を一度実行して記録することとGIFの速度や見た目を調整することを切り離せるところです。

実行にデータベースやネットワークが必要な場合でも、一度カセットを作れば、画像を作り直す環境に同じ依存を用意する必要はありません。

もちろん、カセットに入っているのは録画した時点の結果です。元のソフトウェアが変わった場合は、sessionをもう一度実行して記録を更新する必要があります。現在の実行結果を確認するときは `run` または `record` を使い、同じ結果を繰り返し描画するときは `replay` を使います。

### 一つのsessionから複数の形式を出力する

端末の実行例は、画像にするとREADMEで見やすくなります。一方で、画像の中にある文字は検索やコピーがしづらくなります。また、CIから扱う場合は、画像よりも構造化された結果の方が便利です。

そこでshellfieでは、同じsessionから次の形式を出力できます。

種類 | 形式
--- | ---
静的な表示 | PNG、WebP、SVG、HTML
アニメーション | GIF、アニメーションWebP、APNG、MP4、WebM、PNGシーケンス
トランスクリプト | TXT、ANSI、JSON、asciinema v2

先ほどの例では、文字を選択できるSVGと、プレーンテキストのトランスクリプトを同時に作っています。HTMLも端末の見た目を保ちながら、文字列として読める形で出力します。

一つのsessionに複数の `capture` を置き、途中の画面ごとに別の出力を作ることもできます。たとえば、インストール前、実行中、完了後の画面を、一度のsessionからそれぞれ生成できます。

## session設定を実行する場合の注意点

`generate` は設定に書かれた内容を実行しませんが、`run` と `record` はコマンドを実際に実行します。信頼できないsession設定をそのまま実行せず、事前に内容を確認してください。

sessionには、環境変数の許可リスト、全体とステップごとのタイムアウト、出力量の上限、作業ディレクトリをsessionのルート以下へ制限するポリシー、出力のマスキングなどがあります。終了時には、残った子プロセスやプロセスグループも停止します。

ただし、これらは信頼できないコマンドを安全に実行するためのサンドボックスではありません。実行内容を隔離したい場合は、Dockerなどと組み合わせる必要があります。

shellfie側の制約は、意図しない長時間実行、出力の肥大化、秘密情報の録画、パスの取り違えなどを減らすために用意しています。任意のコマンドを安全に実行できるようにするための機能ではありません。

## shellfieの実装

### 端末を画面として扱う

sessionでは、Ruby標準添付の `PTY` を使ってシェルを起動します。端末サイズを設定し、別スレッドで出力を読み取り、受け取ったバイト列を内部の `TerminalScreen` へ渡しています。

```ruby
@master, @slave, @pid = PTY.spawn(
  env, shell, *args,
  chdir: cwd,
  unsetenv_others: true
)
@master.winsize = [terminal[:rows], terminal[:columns]]
@reader_thread = Thread.new do
  loop do
    append_terminal_chunk(
      decode_terminal_bytes(@master.readpartial(4096))
    )
    break if @reader_error
  end
rescue EOFError, Errno::EIO, IOError
  nil
ensure
  append_terminal_chunk(decode_terminal_bytes("", final: true))
end
```

`PTY.spawn` からmaster側とslave側のIO、子プロセスのPIDを受け取り、master側から端末の出力を読み取ります。読み取り用のスレッドでは、`readpartial(4096)` で受け取ったバイト列をUTF-8として扱える単位までつなぎ直し、`append_terminal_chunk` へ渡しています。

端末の出力は、単に改行で区切られた文字列ではありません。`\r` で行頭へ戻り、backspaceでカーソルが戻り、ANSI escape sequenceによって色やカーソル位置が変わります。行の消去、文字の挿入と削除、スクロール領域、代替画面などもあります。

さらに、画面上の一文字とRubyの `String` 上の一文字も、必ずしも一致しません。全角文字は2セルを使います。結合文字や絵文字は、複数のコードポイントで一つの書記素クラスターを構成することがあります。また、PTYから出力を読み取るタイミングによっては、一つのUTF-8文字が複数の読み取りに分かれている場合もあります。

そのため、shellfieでは端末画面を、行と列を持つセルの集合として管理しています。PTYから受け取った出力を順番に適用し、カーソル移動、消去、折り返し、スクロールなどを反映した上で、その時点の画面を描画します。

`TerminalScreen#feed` では、読み取った文字列を通常の文字、制御文字、CSI sequenceなどのトークンへ分け、順番に処理しています。

```ruby
def feed(text)
  input = text.to_s.dup.force_encoding(Encoding::UTF_8).scrub
  input = discard_control_prefix(input)
  return self if input.empty? && @discarding_control

  input = @pending_control << input
  if @graphics_policy == "error" && input.match?(AnsiNormalizer::GRAPHICS_CONTROL_PREFIX)
    raise ValidationError, "Terminal graphics are not supported; use window.graphics_policy: ignore to discard them"
  end
  input, @pending_control = split_incomplete_control(input)
  input.scan(TOKENS).each { |token| process(token) }
  self
end
```

通常の文字が来た場合は、書記素クラスターの表示幅を調べてセルへ書き込みます。2セルを使う文字では、後ろのセルへ `CONTINUATION` を置き、一つの文字の続きであることが分かるようにしています。

```ruby
def write(grapheme)
  return if extend_previous_grapheme(grapheme)

  width = TextMetrics.grapheme_width(grapheme)
  return if width.zero?
  newline if @wrap_pending
  newline if @column + width > @columns

  clear_wide_cell(@row, @column)
  @cells[@row][@column] = @ansi_parser.parse(grapheme).first
  @cells[@row][@column + 1] = CONTINUATION if width == 2 && @column + 1 < @columns
  @column += width
  if @column >= @columns
    @column = @columns - 1
    @wrap_pending = true
  end
end
```

端末に表示された文字を画像へ描くだけなら、それほど難しくないだろうと思っていました。しかし、実際に作ってみると、端末は文字列というよりも、入力された命令によって状態が変化する画面として扱う必要がありました。今回shellfieを作っていて、一番面白かったところです。

この仕組みによって、通常のコマンドだけではなく、画面を書き換えるCLIや代替画面を使うTUIも扱えるようになっています。

### compose、session、カセットを同じ出力へ変換する

compose設定では、`lines` と `frames` をANSI付きの描画セグメントへ変換します。sessionとカセットでは、端末のイベントを `TerminalScreen` へ適用し、その時点の画面を構成します。
実際にsessionを動かした場合は `SessionRunner#run` が、カセットを再生する場合は `Cassette.read` が、それぞれ `Session` を返します。

```ruby
# run / record
session = SessionRunner.new(config).run

# replay
session = Cassette.read(input)
```

出力するときは、どちらも `Session#render_config` で通常の `Config` へ変換します。アニメーションなら端末イベントごとの画面を `Frame` にし、静的な出力なら最後の画面を `Line` にしています。

```ruby
if animated
  frames = []
  each_snapshot do |event, snapshot|
    frame = Frame.new(
      screen: snapshot,
      delay: [(event[:delay].to_f * 1_000).round, 1].max
    )
    frames << frame
  end
  Config.new(**base, frames: frames)
else
  lines = (lines || screen.render_lines).map { |line| Line.new(output: line) }
  Config.new(**base, lines: lines)
end
```

入力の経路は異なりますが、最後は共通のテーマと出力処理へ渡します。そのため、手で書いたcompose設定、実際に動かしたsession、保存済みのカセットのどれからでも、同じ形式のPNG、SVG、HTML、アニメーションなどを生成できます。

`Renderer` は拡張子から出力先を選びます。SVGとHTMLだけはそれぞれのrendererへ渡し、それ以外の静止画はImageMagickを使う共通の処理へ渡しています。

```ruby
render_method = {
  "svg" => :create_svg_image,
  "svg-raster" => :create_svg_raster_image,
  "html" => :create_html
}.fetch(extension, :create_image)

send(
  render_method,
  lines,
  temporary_path,
  scale: scale,
  shadow: shadow,
  transparent: transparent
)
```

ラスター画像はImageMagickで描画します。SVGはPNGを埋め込まず、文字と図形から直接生成しているため、SVG内の文字列を選択できます。動画やAPNGのエンコードにはffmpegを使っています。なお、SIXEL、Kitty graphics protocol、iTerm2 inline imagesのような端末向け画像プロトコルは、現在描画していません。設定によって無視するか、受け取った時点でエラーにできます。

## YAMLを編集、検証するためのコマンド

設定できる項目が増えてくると、YAMLのキーを間違えたり、最終的にどの値が使われるのか分かりづらくなったりします。そのため、画像を生成する以外にも、設定を編集、検証するためのコマンドを用意しました。

```console
shellfie new terminal.yml --template static
shellfie format terminal.yml
shellfie validate terminal.yml
shellfie compile terminal.yml --format json
shellfie inspect terminal.yml --json
shellfie watch terminal.yml -o terminal.png
shellfie doctor
```

`new` は、static、animation、run、TUI、CIなどのテンプレートから設定を作ります。`format` はYAMLを正規化し、`validate` はファイル名、行、列を含む診断を表示します。

`compile` は、`include` や変数などを解決した後の設定を確認するためのコマンドです。`inspect` では、出力サイズ、フォント、解決済みの設定、必要なリソースの見積もりなどを確認できます。

また、`schema` コマンドから `version: 1` と `version: 2` のJSON Schemaを出力できます。YAML Language Serverへ指定すれば、エディター上で補完と検証を利用できます。

共通のテーマやステップは、別のYAMLから `include` できます。sessionでは、変数、再利用可能な `step_sets`、`repeat`、OS、シェル、Rubyのバージョンなどに応じた `if` も利用できます。展開数には上限があり、循環参照はエラーになります。

## CIで生成物の更新漏れを検出する

YAMLと生成した画像を同じリポジトリへコミットしていると、YAMLだけを変更して画像の更新を忘れることがあります。

`generate --check` は、既存の出力が現在の設定から生成されるものと一致するかを確認します。古くなっている場合は、出力を書き換えずに失敗します。

リポジトリには、Dockerを使ったGitHub Actionも含めています。

```yaml
- uses: ydah/shellfie@main
  with:
    input: examples/simple.yml
    output: docs/terminal.png
    check: "true"
```

これによって、Pull Request上でYAMLと画像のずれを検出できます。通常の生成に使い、CIで画像を更新する構成にもできます。

また、`--manifest` を指定すると、入力設定と出力のハッシュ、Ruby、OS、ImageMagick、ffmpeg、解決されたフォントのフィンガープリントなどをJSONへ記録します。同じYAMLから異なる結果が生成された場合に、描画環境の違いを調べるための情報として使えます。

画像や動画の生成では、一時ファイルやピクセル数が大きくなりがちです。そのため、入力サイズ、フレーム数、ピクセル数、描画量、一時ディスク使用量などを事前に見積もります。設定した上限を超える場合は、重い処理を始める前にエラーにします。

出力は一時ファイルへ書いてから置き換えます。生成に失敗した場合は既存の出力を維持し、途中まで作られたアニメーションファイルや一時ファイルは削除します。

## おわりに

CLIツールのデモGIFを作るたびに端末を整えて撮り直すのが面倒だったので、YAMLから何度でも同じデモを作れるshellfieを作りました。

最初は、YAMLに書いた文字列を画像にするだけの小さなツールになるつもりでした。しかし、実際のコマンドを動かした結果も確かめたい、実行と見た目の調整を分けたい、TUIも扱いたい、と作っていくうちに、端末そのものを画面として扱うところまでやってきました。是非使ってみてください。
